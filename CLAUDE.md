# EE2026 Rubik's Cube Solver

2x2 Rubik's cube solver on the Basys3 FPGA (EE2026, NUS).

## Layout

* `src/pkg/cube_defs.vh`: shared constants and helper functions
* `src/top/`: top module and clock ticks
* `src/inputs/`: buttons, switches, mouse
* `src/logic/`: game FSM, move controller, cube engine, scrambler, solver, camera
* `src/render/`: view ROM and cube renderer
* `src/outputs/`: VGA, OLED, LEDs, 7-segment
* `docs/module_ports.txt`: port list of every module

## Language

* Verilog-2001 only. Source files are `.v`; the shared header is `src/pkg/cube_defs.vh`.
* No SystemVerilog: no `logic`, `int`, `always_ff`/`always_comb`, `package`/`import`, `typedef`, `'0`, size casts like `3'(x)`, or `return` in functions.
* Every `.v` file starts with `` `timescale 1ns / 1ps `` on line 1 (not in `cube_defs.vh`).
* Every module does `` `include "cube_defs.vh" `` inside the module, after the port list. Never add an include guard to `cube_defs.vh`.
* Port lists follow `docs/module_ports.txt`.

## Git

* Commit messages: exactly one line, all lowercase, conventional prefix (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`, `test:`).
* No `Co-Authored-By` trailers or AI attribution in commits.
* PRs: title only (same format as commit messages), empty description. No body text, no "Generated by" footer.
* Work on a branch and open a PR; don't push straight to `main`.
